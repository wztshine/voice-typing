# 语音打字 (voice-typing)

按住 **右侧 Ctrl** 说话，松开后自动把识别出的文字输入到当前光标位置。全程本地运行，不联网。

> 热键可改：双击 `设置热键.bat`，按一下你想用的键即可（当前为右侧 Ctrl，因为 F9 在 Typora 里是「打字机模式」）。

## 目录

```

  models\
    FireRedASR2-AED\      识别主模型 (1.1B, 中文 SOTA; model.fp16.pth.tar 是 fp16 权重)
```

## 使用

- 按住 **右侧 Ctrl** 说话、松开输入（热键可改，见下文）
- **F10**（按一下开始录音、再按一下结束，适合长段口述）
- 首次启动需加载模型，约 3~5 秒，之后常驻显存
- 识别结果通过「剪贴板 + Ctrl+V」输入，原剪贴板内容会自动还原；识别文本带隐私标记，不会进入 Win+V 剪贴板历史，也不会同步云剪贴板
  （连续两次识别也会还原到最早的内容；原内容是**图片/文件**时无法备份，
  会被识别文字替换，日志会提示一句）
- 每次说话长度建议 1~30 秒；说完整句，识别效果最好
- 说话时屏幕底部会弹出浮窗：绿点 + 计时 + 音量条表示**正在录音**，黄点「识别中…」，蓝点「✓ 已输入」并显示文字，约 2 秒后自动消失

## 屏幕浮窗（录音状态）

录音时屏幕底部居中会显示一个小浮窗，让你随时知道程序有没有在听：

| 状态 | 显示 |
|---|---|
| 开始录音 | 绿点 + `● 录音中 1.2s` + 音量条（随说话跳动） |
| 说完 | 黄点 + `识别中…` |
| 识别完成 | 蓝点 + `✓ 已输入` + 最终文字，2.2 秒后隐藏 |
| 没声音 | 提示「没检测到声音，检查麦克风」 |
| 说话太短 | 提示「说话太短」 |

特点：

- **不抢焦点**：浮窗带 `WS_EX_NOACTIVATE`，弹出时不会打断你正在打字的窗口
- **鼠标穿透**：`WS_EX_TRANSPARENT`，点不中、不会挡住底下的按钮
- 不在任务栏显示（`WS_EX_TOOLWINDOW`），置顶显示
- 音量条会跟着你说话跳动，一眼就能确认麦克风在工作

**默认只显示状态，不做边录边识别**（`live_preview: false`）：

- 录音期间 GPU **完全不跑识别**，只在你松手后跑一次
- 打开后，说话期间会每隔约 1~2 秒把已录到的音频重新识别一遍，GPU 几乎全程在算，还会发热
- 显存占用不变（用的还是同一个模型），多出来的是**计算时间**；而且松手后的正式识别要等正在跑的草稿结束，可能多等 1~2 秒

如果想让长句录音时也边录边显示识别草稿（灰色文字，每 1.2 秒刷新一次），在 `config.json` 里打开：

```json
{ "live_preview": true, "live_after_sec": 3.0 }
```

完全不要浮窗：`{ "show_ui": false }`。

## 启动与停止

**双击就行**，四个脚本覆盖全部操作：

| 双击 | 作用 |
|---|---|
| `启动语音输入(后台).vbs` | 后台静默启动，无任何窗口 |
| `停止语音输入.bat` | 停止（只杀 voice_typing，不影响别的 python 程序） |
| `重启语音输入.bat` | 停止 → 重新后台启动 → 显示状态 |
| `查看状态.bat` | 是否运行 / 显卡占用 / 最近 10 条日志 |
| `启动语音输入.bat` | 前台启动，有控制台，实时显示识别文字 |

程序是**无窗口后台运行**（`pythonw.exe`），任务栏看不到图标，靠热键工作（当前右 Ctrl / F10）。

命令行等价写法：

```powershell
cscript //nologo G:\AZ\stt\silent_start.vbs       # 后台启动
G:\AZ\stt\启动语音输入.bat                          # 前台启动
powershell -ExecutionPolicy Bypass -File G:\AZ\stt\stop.ps1   # 停止
Get-Process pythonw                               # 确认是否在跑
```

日志：`G:\AZ\stt\logs\voice_typing.log`（超过 3MB 自动轮转为 `.log.1`）

## 命令行参数

```
启动语音输入.bat                 # 默认
启动语音输入.bat --list-devices   # 列出麦克风设备
启动语音输入.bat --device 1      # 指定输入设备(默认走系统默认麦克风)
启动语音输入.bat --type          # 不用粘贴，改为逐字模拟输入(个别软件粘贴无效时用)
启动语音输入.bat --no-punc       # 关闭标点恢复
启动语音输入.bat --fp32          # 用 FP32 推理(更慢、更占显存, 更稳)
启动语音输入.bat --dry-run       # 只识别不输入(排查用)
启动语音输入.bat --file a.wav    # 转写单个音频文件(打印 原始 + 后处理 两个版本)
启动语音输入.bat --no-post       # 关闭输出后处理(保留原始识别文本)
```

`--file` 可以和其他选项组合，例如 `--file a.wav --no-post --no-punc`；
不是 16kHz 单声道的音频（44.1kHz、立体声等）会自动重采样/混成单声道；
文件不存在、格式损坏、空文件或短于 0.05 秒时只打印一行中文提示并以退出码 2 结束，
不会再抛 Python 堆栈。

`--type` 逐字输入走 Windows 的 Unicode 注入，中英文/数字/emoji 都可靠，
不受输入法和键盘布局影响（早期版本用 pynput 会丢字，已修）。

## 实测性能 (RTX 2060 12G, FP16)

| 音频时长 | 总耗时 (beam=3) | 实时率 | beam=1 总耗时 |
|---|---|---|---|
| 2.3s 中文 | 0.40s | 0.17 | 0.24s |
| 10s 中文 | 1.63s | 0.15 | 0.70s |
| 22s 中文 | 3.53s | 0.16 | 1.52s |

耗时构成（以 10s 音频为例）：VAD 0.04s + ASR 1.6s + 标点 0.02s，**几乎全花在识别主模型上**。

调快速度的两个办法：

1. `config.json` 里把 `"beam_size"` 从 `3` 改成 `1`：识别速度约**快一倍**，日常口述中文几乎看不出差别（上面的测试文本完全一致），复杂/嘈杂环境准确率会略降
2. 关掉实时草稿 `"live_preview": false`：长句录音时不再后台重复识别

显存峰值 **2.2GB**，模型常驻。冷启动加载模型约 **3~5 秒**（fp16+mmap 加载，见下）。

### 半精度与内存占用

RTX 20 系（Turing，SM<8.0）**没有原生 bf16**，但 PyTorch 会谎报支持，
库于是选了 bfloat16 —— 在 2060 上实测比 fp16 **慢一倍**。程序启动时会自动检测并强制 fp16：

```
显卡没有原生 bf16 (SM<8.0), 已改用 FP16 推理(快一倍)
```

| 项目 | 优化前 (fp32 权重 + bf16) | 现在 (fp16 权重 + mmap) |
|---|---|---|
| 3s 音频识别 | 0.60s | **0.21s** |
| 模型加载 | 14.7s | **2.5s** |
| 进程内存常驻 | 4.59 GB | **1.89 GB** |
| 进程内存峰值 | 9.73 GB | **3.01 GB** |
| 显存 | 2.57 GB | 2.21 / 2.61 GB |
| 权重文件 | 4.41 GB | **2.20 GB** |

原理：fp32 的 4.4GB checkpoint 在加载时会被复制两份（`torch.load` 一份、`load_state_dict` 一份），
用完那 4.4GB 也未必还给系统。现在改成 fp16 权重 + `mmap` + `assign=True`，
并且**直接在显卡上建模**，内存里不再出现整份权重。

权重转换只需跑一次：

```
G:\AZ\stt\venv\Scripts\python.exe make_fp16.py
```

生成 `models\FireRedASR2-AED\model.fp16.pth.tar`（2.2GB）后程序会自动优先使用；
想回退就删掉这个文件，或把 `config.json` 的 `"fast_load": false`。

原来的 `model.pth.tar`（4.41GB）**已经删掉**，G 盘因此多出 4.4GB。
现在只剩 fp16 权重，所以 `--fp32` 和 `"fast_load": false` 都会自动落回 fp16；
真要恢复 fp32 原文件就重新下载（会补齐缺失的文件）：

```
G:\AZ\stt\venv\Scripts\python.exe dl.py
```

> 再快就只能换模型了：`FireRedASR2-AED` 已经是这个系列里最快的（LLM 版 8.3B 更准但慢 5~10 倍）；
> 纯中文追求低延迟可以考虑阿里 Paraformer（非自回归，实时率约 0.02~0.05），但准确率和热词支持不如现在这套，
> 需要重新搭环境，没有明显必要。

## 功耗与显存

实测（RTX 2060 12G，用 Windows 的 GPU 计数器按进程统计）：

| 状态 | 本程序 GPU 占用 | 本程序 CPU | 整卡功耗 |
|---|---|---|---|
| 常驻、没在说话 | **0%** | 0% | 45~50W（与平时一样，是别的程序在用） |
| 正在识别（10s 音频） | 平均 66%，持续 1.6~2s | 少量 | 约 130W，峰值 156W |
| 识别结束 | 立刻回到 0% | 0% | 回到 45~50W |

- **显存常驻约 2.2~2.6GB**（模型 + CUDA 上下文），这期间几乎不耗电：显存只要通电就会刷新，用多用少功耗差不多
- 对照实验：模型常驻时整卡约 54W，完全停止服务后约 50W，**差 2~8W**（含测量噪声）
- 电费估算：按 4W 常驻算，24 小时开机约 2.9 度/月（1.6 元）；每天用 10 小时约 1.2 度/月（0.7 元）
- 真正会明显增加 GPU 负载的只有 `live_preview`（录音时反复跑识别），默认已关闭
- 打游戏/跑大模型前如果显存紧张，双击 `停止语音输入.bat` 释放这 2.2GB，再启动等 3~5 秒

常驻的单个 `pythonw.exe` 约 **1.9GB 内存**（任务是 31.8GB 的机器，约占 6%）：

## 改热键

**最简单的办法**：双击 `设置热键.bat` → 按一下你想用的键 → 自动保存并重启。

- 只接受 **F1~F24 / 右侧 Ctrl / ScrollLock / Pause / PrintScreen / Insert / Menu** 这类平时不用的键
- 单独的 Ctrl / Shift / Alt 会被拒绝（容易和快捷键冲突），普通字母也被拒绝（打字会误触发录音）
- 想改「按一下开始/再按一下结束」的那个键：`设置热键.bat --toggle`

也可以直接编辑 `config.json`（改完双击 `重启语音输入.bat`）：

```json
{
  "hotkey": "ctrl_r",
  "toggle_key": "f10"
}
```

键名写法：`ctrl_r`（右Ctrl）、`f7`、`f8`、`pause`、`print_screen`、`insert`、`none`（关闭）。

> 完整配置项见下方「配置文件 config.json」。

> 提示：F9 在 Typora 里是「打字机模式」，F10 在部分软件里会激活菜单栏，所以默认选了右侧 Ctrl。

## 自定义热词

编辑 `hotwords.txt`（或双击 `设置热词.bat`，保存后自动重启），一行一个词：

```
Typora
FireRedASR
知识库
大语言模型
```

生效方式有两层：

1. **解码期偏置**：识别时给这些词加分，让模型更倾向输出它们（真正提高识别率）
2. **输出期校正**：英文按你写的大小写修正（例如写成 `Typora`，模型输出 `typora` 也会被改回来）

注意事项：

- `#` 开头是注释；改完必须重启（`设置热词.bat` 会自动重启）
- **带数字的词无效**（如 `Qwen3`），因为模型词典里没有数字 token，会被自动跳过并在日志里提示
- 偏置强度在 `config.json` 里：`"hotword_bonus": 2.0`。调大到 4~6 更强势，但可能把发音相近的普通词误识别成热词；设 0 关闭
- 启动日志会打印 `热词已启用 N 条 (偏置 x.x): [...]`，可用 `查看状态.bat` 确认

## 断句/标点调优

模型自带 VAD（语音端点检测），原版默认**停顿 0.2 秒就切断**，每段单独识别并各自补一个句号，
所以说话中间稍微想一下就会变成「但是。我心里……」「然后他就。自己断句了。」

现在已经调成这样：

| 行为 | 默认值 | 配置项 |
|---|---|---|
| 停顿多久才算说完一句 | 0.6 秒 | `vad_min_silence_ms` |
| 两段之间停顿小于多久就合并成一段识别 | 1.4 秒 | `vad_merge_silence_ms` |
| 段间停顿小于多久改用**逗号**连接 | 2.5 秒 | `join_gap_ms` |
| 单段最长多久（超过强制切开） | 20 秒 | `vad_max_speech_ms` |

实测效果（同一句话中间插不同长度停顿）：

| 停顿 | 结果 |
|---|---|
| 0.5s | 1 段：`你好世界，你好世界。` |
| 1.6s | 2 段但用逗号合并：`你好世界，你好世界。` |
| 3.0s | 保留句号：`你好世界。你好世界。` |

想**更少断句**：把 `join_gap_ms` 调大到 3500~4000；想**按停顿自动断句**：调小到 1200。
改完双击 `重启语音输入.bat` 生效。

## 输出后处理（规则改写）

识别出来的文字在上屏前还会过一遍**纯规则改写**（`postprocess.py`）。它不是模型，就是正则 + 查表，
毫秒级完成、不占显卡、完全离线。

**设计原则：宁可不改，也不改错。**只处理"形状稳定"的东西，不猜内容。

| 规则 | 例子 |
|---|---|
| 日期/数字转阿拉伯 | `二零二六年三月十五号` → `2026年3月15号` |
| 金额转阿拉伯 | `三百块钱` → `300块钱`、`五元` → `5元` |
| 百分比 | `百分之三十` → `30%`、`百分之三点五` → `3.5%` |
| 时间 | `下午三点半` → `下午3点半`、`四点十五分` → `4点15分` |
| 逐字母拼读（转小写） | `H I O U` → `hiou`、`HIou.` → `hiou.` |
| 被空格拆散的英文 | `S t r I p c h a t` → `stripchat`（热词里有就还原成 `Stripchat`） |
| 中文"点"当域名点 | `www点baidu点com` → `www.baidu.com`、`点com` → `.com` |
| 网址/拼读域名 | `三w点儿百度点儿com` → `www.baidu.com` |
| 字母+中文数字 | `f九` → `F9`、`gpt四` → `GPT4` |
| 固定缩写大写 | `po` → `PO`（只在独立出现时，不会碰 `post`） |
| **整段只有数字** | `三千两百八十九。` → `3289。`、`幺八八幺幺幺。` → `188111。`、`三点五。` → `3.5。` |
| 口语冗余 | 句首`嗯，`/`那个，`/`就是说，`删掉；`我我我` → `我` |

**刻意不改的**（防止误伤）：

- 没有单位的数字：`一起`、`二手`、`三思`、`一点累`、`十分重要`、`一百万用户`
- **句子里夹着汉字的数字**：`我买了三千两百八十九个` 不动（只有整段是数字才转）
- 没有"半/分"的`两点`、`三点`（避免把「有一点累」改成「有1点累」）
- 品牌/普通词里的数字：`三元牛奶` 不会被改成 `3元牛奶`（元后面必须跟标点或结尾才转）
- 正常叠词：`人人`、`常常`
- 英文单词：`post 一下` 不会被改成 `POST1下`

### 整段只有数字

最常用的一种情况：你单独念一串数字，它转成阿拉伯数字。

| 念出来的 | 上屏 |
|---|---|
| 三千两百八十九。 | `3289。` |
| 二零二六。 | `2026。` |
| 一九九八。 | `1998。` |
| 幺八八幺幺幺。 | `188111。` |
| 一百。 | `100。` |
| 三点五。 | `3.5。` |
| 零零三。 | `003。`（前导零保留） |
| 一二三四五六七八九十。 | `12345678910。`（逐位念，`十` 按 10 展开） |
| `幺` | 按 `1` 处理（念电话号码常用） |

**触发条件**：整句/整段（逗号、句号、顿号等分隔开的部分）必须**全部是数字**。

**逐位读法 vs 数词**：中文数词里数字和单位（十/百/千/万）是交替出现的，
所以「连续 3 个以上数字字符」只可能是逐位念的，会逐位转换而不是整体求值：

- `一二三四五六七八九十` → `12345678910`（以前会被当成数词整体算成 `90`，把前面 8 位吃掉）
- `一二三` → `123`（以前会算成 `3`）
- `二十三`、`一百零五`、`三千两百八十九` 是标准数词，仍按整体求值
- `二三十`、`两三千` 这种口语约数仍按整体求值（`30`、`3000`）

- `我买了三千两百八十九个。` → 不动（夹了汉字）
- `这个月预算大概三千两百八十九。` → 不动（夹了汉字）
- `两点的会。` → 不动（没有"半/分"，不当时间）

### 英文大小写与逐字母拼读

中文模型对英文大小写没有可靠建模，逐字母念的时候尤其明显：念 `H I O U` 可能输出 `HIou`（中间的 I 大写、ou 小写）。

规则按这个优先级处理：

1. **热词优先**：`hotwords.txt` 里的词，输出后按你写的标准写法修正（大小写不敏感）。
   例如加了 `Stripchat`，`S t r I p c h a t` / `stripchat` / `STRIPCHAT` 都会变成 `Stripchat`
2. **拼读转小写**：整句只是一个短的英文串，且大小写"混乱"（既非全大写、全小写，也非首字母大写）时，统一转小写
   - `HIou` → `hiou`、`H I O U` → `hiou`、`StrIpchat.com` → `stripchat.com`
3. **品牌名白名单**：这些保持原样，不会被改成小写
   `iPhone`、`iPad`、`iOS`、`macOS`、`GitHub`、`YouTube`、`PowerShell`、`OpenAI`、`ChatGPT`、`DeepSeek`、`PyTorch`、`Typora`、`WeChat`、`WeBox`…（完整列表在 `postprocess.py` 的 `DEFAULT_KEEP_CASE`）
4. **全大写 / 首字母大写不动**：`GPU`、`PO`、`Hello`、`readme` 都会保持原样

想在白名单里补充自己的品牌名，在 `config.json` 加：

```json
{ "latin_keep_case": ["MyBrand", "SomeTool"] }
```

> 注意：拼读转小写只对"整段就是一个英文串"生效；`HIou 你好` 这种中英混排不动。

### 网址/域名

| 念的 | 上屏 |
|---|---|
| `三w点儿百度点儿com` | `www.baidu.com` |
| `三W点淘宝点com` | `www.taobao.com` |
| `www点知乎点com` | `www.zhihu.com` |
| `hello点百度点com` | `hello.baidu.com` |
| `点com` | `.com` |
| `www点baidu点com` | `www.baidu.com` |

规则细节：

- **`三w` → `www`**：中文里念 www 的常见说法（`3w` 不转，避免误伤"月薪3w"）
- **`点儿` → `点`**：儿化音，`一点儿也不累` → `一点也不累`，`有点儿` → `有点`
- **中文标签转拼音**：`百度` → `baidu`（用 `pypinyin`，已装在 venv）
- **去掉网址结尾的句号**：`www.baidu.com。` → `www.baidu.com`，`GitHub.com.` → `GitHub.com`
  - 只对"以已知后缀结尾"的网址生效；`你好。`、`Hello.`、`GitHub.` 的句号都保留
- 只转换**已知后缀**结尾的整段：`com / cn / net / org / io / ai / cc / top / me / tv / info / xyz`
- 依赖 `pypinyin`（已装在 venv）。重装环境后补一句：
  `G:\AZ\stt\venv\Scripts\pip install pypinyin`
  没有它时只是**中文域名不转拼音**，数字、拼读、句号等功能都正常（启动日志会显示 `拼音模块: 未安装`）
- 保守限制：必须有 `www`/英文前缀才转拼音，所以单独说 `百度点com` 保持原样，避免把「我觉得点com」这类句子误改成域名

### 自定义替换 replacements.txt

只建议放**模型每次都错成同一个样子**的词：

```
typewriter => Typora
太坡拉 => Typora
```

- 一行一条，`#` 开头是注释，长词优先匹配
- 改完双击 `重启语音输入.bat` 生效，启动日志会打印加载了几条
- **纯数字的原词不要加**（会误伤日期里的数字）
- 如果同一个词"有时对、有时错成别的字"（比如人名），固定替换没用，应该加进 `hotwords.txt` 用热词偏置

| 键 | 默认 | 说明 |
|---|---|---|
| `hotkey` | `ctrl_r` | 按住说话键；`none` 关闭 |
| `toggle_key` | `f10` | 按一下开始/再按结束；`none` 关闭 |
| `hotword_bonus` | `2.0` | 热词偏置强度，0 关闭，4~6 更强势 |

| `vad_merge_silence_ms` | `1400` | 间隔小于此值合并成一段识别 |
| `join_gap_ms` | `2500` | 段间停顿小于此值用逗号连接，0 关闭 |
| `vad_max_speech_ms` | `20000` | 单段最长时长，超过强制切开 |
| `beam_size` | `3` | 解码搜索宽度；`1` 最快（约快一倍），`3` 更准 |
| `postprocess` | `true` | 输出后处理总开关 |
| `filler_removal` | `true` | 去口语冗余（嗯/那个/重复字） |
| `number_norm` | `true` | 数字/日期/金额/百分比转阿拉伯数字（支持口语省略式：四千五→4500、一万二→12000、一百五→150、十万八→108000；带保护：“一点/两点”不误转、“一元一次方程”不误伤） |
| `trailing_punct` | `auto` | 末尾标点策略：`auto` 短句去掉/长句保留；`strip` 总去掉；`keep` 总保留。问号、叹号、省略号等承载含义的符号默认不删 |
| `trailing_punct_max_len` | `15` | `auto` 模式下，不超过这个字数的句子去掉末尾标点 |
| `trailing_punct_keep` | `？！…～~` | 永不删除的末尾符号（去掉会改变句子含义/语气）；设为 `""` 则短句连问号也去掉 |
| `uppercase_abbr` | `["po"]` | 这些独立出现的英文缩写统一大写 |
| `latin_keep_case` | 无 | 额外的品牌名白名单（不转小写），如 `["MyBrand"]` |
| `show_ui` | `true` | 屏幕底部浮窗开关 |
| `live_preview` | `false` | 长句边说边显示识别草稿（录音时反复跑识别，默认关） |

| `live_max_sec` | `10.0` | 草稿只取最近多少秒音频 |
| `device` | `null` | 麦克风设备号（`--list-devices` 查看） |
| `sample_rate` | `16000` | 录音采样率（模型要求 16k，不建议改） |
| `min_sec` | `0.35` | 录音短于此值直接忽略，不送识别 |
| `max_sec` | `120` | 单次录音最长时长（秒） |
| `enable_vad` | `true` | 语音端点检测（自动去掉前后静音） |

## 模型升级/替换

想换模型只需改 `voice_typing.py` 里 `load_model()` 的 `asr_model_dir`（例如换成
`FireRedASR2-LLM` 8.3B，更准但 2060 上单句约 3~5 秒），或把 `asr_type="aed"`
改成 `"llm"` 并下载对应权重。

## 已知限制

- 目标窗口若以管理员权限运行，普通权限的程序无法向其注入按键（UIPI 限制）。此时以管理员身份启动本程序。
- 热键在某款软件里被占用时，用 `设置热键.bat` 换一个。
- 全屏独占游戏里无法输入。
